# 1. 도입 준비사항

준비물은 **① 실행 환경 → ② 계정·연동 → ③ 데이터 → ④ 발송 인프라** 순으로 갖춥니다.
아래 **A~D가 필수**, **E는 조건부(대량 발송·특정 채널)**, **F는 선택**입니다.

---

## A. 실행 환경 (운영 PC)

도구를 구동하는 PC(운영 담당자 노트북)에 아래가 설치돼 있어야 합니다. 대부분 밀버스 측에서 세팅하지만, 고객사 PC에서 직접 운영할 경우 필요합니다.

| 항목 | 내용 | 확인 방법 | 필수도 |
|---|---|---|---|
| **Node.js** | 정의서(xlsx) 생성·리포트 생성 스크립트 실행 런타임 | `node --version` | 필수 |
| **Claude Code CLI** | 에이전트 본체(오케스트레이터) 구동 | `claude --version` | 필수 |
| **저장소 clone + `npm install`** | `node_modules`는 git에 없음 → 최초 1회 설치 (`exceljs`·`pptxgenjs`·`xlsx`) | `npm list` | 필수 |
| **Python** | xlsx 정의서 파싱 시 사용 | `python --version` | 권장 |

> ⚠️ `npm install`을 건너뛰면 정의서 생성 단계에서 `Cannot find module 'exceljs'` 오류가 발생합니다.
> 경로는 clone 위치를 자동 인식하므로 폴더 위치가 달라도 그대로 동작합니다(별도 치환 불필요).

## B. SFMC 계정 · API 연동

**모든 기능(진단·저니 생성·조회)의 전제**입니다. SFMC와 통신하는 MCP 서버 연결이 여기서 만들어집니다.

### B-1. 계정 · 기능 프로비저닝

| 항목 | 내용 | 필수도 |
|---|---|---|
| MCE 라이선스 | Marketing Cloud Engagement 활성 계정 | 필수 |
| Business Unit | 발송 주체가 될 **대상 BU** 확정 (여러 BU면 어느 BU에 만들지 지정) | 필수 |
| 기능 프로비저닝 | **Journey Builder · Automation Studio · Email Studio · Content/Contact Builder** 활성화 | 필수 |
| 관리자 권한 | Setup(발송 인증·구독센터) 설정이 가능한 계정 | 필수 |

### B-2. Installed Package (API 연동) 생성

Marketing Cloud → **Administration → Installed Packages → New** → **Add Component → API Integration → Server-to-Server** 로 생성하고, 아래 **권한(Scope)** 을 부여합니다.

| 카테고리 | 필요 권한 |
|---|---|
| Email | Read, Write, Send |
| Journeys | Read, Write, Execute |
| List and Subscribers | Read, Write |
| Data Extensions | Read, Write |
| Contacts | Read, Write |
| Automation | Read, Write, Execute |
| SMS | Read, Write, Send |
| Push | Read, Write, Send |

생성 후 아래 4개 값을 확보합니다 → 테넌트별 MCP 엔드포인트 URL 발급에 사용됩니다.

- **Client ID**, **Client Secret**, **MID(Account ID)**
- 인증 URL(`https://xxxxxxxxx.auth.marketingcloudapis.com`)의 **28자리 Subdomain**

### B-3. MCP 서버 연결 (운영 PC에서 1회)

발급받은 원격 엔드포인트 URL을 HTTP transport로 등록합니다.

```bash
claude mcp add --transport http sf-mce-mcp "https://…sfdcfc.net/t/<테넌트ID>/c/<세션토큰>/api/mcp"
```

- 서버 이름은 반드시 **`sf-mce-mcp` 하나로 통일** (이름 변경 시 OAuth 1회 재인증 필요)
- `--transport http` 없이 이름만 주면 로컬(stdio) 서버로 잡혀 연결되지 않음
- `/mcp` 실행 시 `Authentication successful. Connected to sf-mce-mcp.` 가 뜨면 정상

## C. 고객 데이터

캠페인 진단·타깃팅의 원천입니다. **고객 데이터가 SFMC(Data Extension)에 적재**돼 있어야 하며, 정규화된 여러 테이블(고객·주문·상세·제품·쿠폰)이면 에이전트가 JOIN·집계해 **고객 프로파일 DE**를 자동으로 만들어 그 위에서 진단합니다.

### C-1. 원천 데이터 (예: 이커머스 표준)

| 엔티티 | 조인키 | 도출되는 분석값 |
|---|---|---|
| 고객 | member_id (PK) | 로그인·동의·장바구니·생일·등급·포인트 |
| 구매마스터 | order_id, member_id | 누적 주문 수·누적 결제액·최근주문일 |
| 구매상세 | detail_id, order_id, product_id | 선호 카테고리 |
| 제품 | product_id (PK) | 카테고리 |
| 쿠폰 | coupon_id, member_id | 미사용 쿠폰 수 |

### C-2. 분석 핵심 컬럼

캠페인 도출에 쓰이는 신호 컬럼입니다. **날짜·수치 원천 컬럼만 두면 되고**(예: `is_dormant` 같은 플래그 불필요), 휴면·이탈 등 대상 판정은 에이전트가 쿼리로 계산합니다.

| 의미 | 컬럼(예시) | 활용 캠페인 |
|---|---|---|
| 가입일 | `signup_date` | 신규회원 웰컴/온보딩 |
| 마지막 로그인 | `last_login_date` | 휴면 재활성화 |
| 마지막 주문일 | `last_order_date` | 이탈 재구매 유도 |
| 누적 주문·결제액 | `order_count`, `total_spent` | 2차 구매·VIP 등급 |
| 생일 | `birthday` | 생일 쿠폰 |
| 장바구니 | `has_abandoned_cart`, `cart_total_amount` | 장바구니 리마인더 |
| 쿠폰/포인트 만료 | `coupon_expire_date`, `points_expire_date` | 만료 리마인더 |
| 등급·취향·지역 | `grade`, `preferred_category`, `region` | 분기·세분화 |

### C-3. 채널 수신 동의 값 ⭐ 필수

- `email_consent` (이메일) / `sms_consent` (SMS·알림톡) — Boolean(`'True'`/`1`)
- **동의자만 발송 대상**이 됩니다. 실제 발송 인원 = 세그먼트 ∩ 동의 (진단 인원보다 작음)

> 스키마가 위 예시와 다르면 **분석 가이드 문서(`analysis-guide/<고객사>.md`) 1건만** 컬럼명·의미로 갱신하면 됩니다. 측정 세그먼트·기준선·추천 캠페인은 에이전트가 데이터를 프로파일링해 스스로 정합니다.

## D. 발송 인프라

실제 **이메일/메시지 발송**까지 가려면 아래 인증·구성이 필요합니다. 대부분 SFMC Setup(콘솔) 수동 항목입니다.

### D-1. 발송 인증 · 평판 (Deliverability)

| 항목 | 내용 | 확인 위치 | 발송 전 |
|---|---|---|---|
| 도메인 인증 (SAP) | SPF·DKIM·DMARC — 발송 도메인 DNS 등록 | Setup → Sender Authentication Package | **필수** |
| CAN-SPAM 물리 주소 | 이메일 푸터 법정 발신 주소 | Setup → Account Settings | **필수** |
| Reply Mail Management | 회신(반송) 처리 | Setup → Reply Mail Management | 권장 |
| Link/Tracking 도메인 | 클릭·오픈 추적 도메인 브랜딩 | Setup → Domains | 권장 |

### D-2. 발송 구성 (Send Configuration)

| 항목 | 내용 | 점검 | 발송 전 |
|---|---|---|---|
| Sender Profile | 발신자명·From 주소 | 🟢 API 자동 점검 | 필수 |
| Send Classification | Marketing / Operational 구분 | 🟢 API 자동 점검 | 필수 |
| Delivery Profile | Send Classification에 연결 | 🟢 API 자동 점검 | 필수 |
| 구독센터 / Unsubscribe | 수신거부·프로필 센터 | Setup → Subscriber 관리 | **필수** |

> `"세팅 점검해줘"` 한 마디로 D-1·D-2 상태를 `✅구성됨 / ⚠️점검필요 / ❌수동확인`으로 자동 진단받을 수 있습니다(아래 [기능 2-5](#2-5-온보딩--세팅-점검) 참조).

## E. 조건부 준비물

### E-1. 전용 IP · IP 워밍 (대량 발송 시)

신규 전용 IP는 발신 평판을 쌓기 위해 발송량을 점진적으로 늘리는 **워밍**이 필요합니다(API 자동화 불가 — 운영 프로세스).

**표준 4주 램프(권장 상한, 계정 규모에 맞춰 조정):**

| 기간 | 일일 발송량 | 대상 |
|---|---|---|
| Day 1 | ~50 | 최근 30일 오픈/클릭 최우량 고객 |
| Day 2–3 | 100 → 500 | 고인게이지 세그먼트 |
| Week 1 | 1,000 → 5,000 | 오픈율 높은 활성 고객 |
| Week 2 | 10,000 → 50,000 | 활성 고객 확대 |
| Week 3 | 100,000 → 250,000 | 준활성 포함 |
| Week 4+ | 전체 전환 | 전체 구독자 |

- **선행 마일스톤**: 도메인 인증·물리 주소·수신거부 확인은 워밍 시작 **D-7**, 최우량 세그먼트 준비는 **D-3** 까지 완료 권장
- **운영 수칙**: 인게이지 높은 순으로 확대 · 바운스/스팸율 급등 시 전 단계로 롤백 · 일정한 발송 주기 유지

### E-2. 알림톡 / 문자 / 카카오 / SMS 채널 (해당 채널 캠페인 시)

이메일이 아닌 카카오/문자 발송은 SFMC 기본 액티비티가 아니라 **micrm REST 커스텀 액티비티**로 처리합니다.

| 항목 | 내용 |
|---|---|
| micrm 계정 | `sales.micrm.co.kr` 로그인 계정 |
| 브라우저 로그인 세션 | 콘텐츠(seq) 조회는 micrm **웹세션**(쿠키+CSRF)으로만 가능 — 브라우저 로그인 상태 필요 |
| 커스텀 액티비티 설치 | 대상 **BU에 micrm REST 커스텀 액티비티**가 설치돼 있어야 동작 |
| 승인된 알림톡 템플릿 | 카카오 채널 연결 + 승인된 템플릿(모바일 컨텐츠 seq 확보 가능) |

# 2. 사용 가능 기능

## 2-1. 캠페인 진단 · 추천 (STEP 1)

**"필드가 있으니 가능"이 아니라, 실제 데이터 값을 집계해 약점을 찾아 추천**합니다.

- **자율 프로파일링**: 마스터 프로파일을 집계해 지표별 **인원·비율**을 산출하고, 비율이 두드러진(약점) 지표를 우선순위로 추천. 캠페인 목록·기준선을 문서에 하드코딩하지 않고 데이터에서 도출합니다.
- **입력 2갈래**:
  - **리스트업(의도 없음)** — "어떤 캠페인 만들 수 있어?" → 전체 진단표 + 비율 높은 순 추천 목록
  - **의도 포함** — "신규회원 캠페인 만들어줘" → 해당 신호의 상세 후보 표(복잡도 단순→복합, 2~5개)
- **분석 리포트 자동 생성**: 리스트업/진단 직후, 결과를 고객 전달용 리포트로 자동 산출
- **발송 인원 계산**: 캠페인 선택 후 세그먼트 조건 + **채널 동의 필터**를 적용해 진입 DE 생성

**진단표 예시:**

```
고객 데이터 분석 (모수 N명)
지표                 | 인원   | 비율 | 추천 캠페인
1회성 구매자          | 6,400 | 64% | 2차 구매 유도
휴면 (로그인 90일+)   | 3,500 | 35% | 휴면 고객 재활성화
이탈위험 (주문 90일+) | 2,528 | 32% | 이탈 고객 재구매 유도
```

## 2-2. 캠페인 기획 · 정의서 (STEP 2)

- **Journey Plan 설계** — 진입 소스 · 스케줄 · 재진입 · 단계 구성 · 분기 조건을 설계
- **정의서(xlsx) 자동 생성** — **캠페인 개요** 탭 + **저니 구조** 탭 2탭 구조, 캠페인 ID 자동 채번(`CP_001`, `CP_002`…)
- **실행 모드 2가지**:

| 모드 | 동작 |
|---|---|
| **수동(Manual)** | 진입·스케줄·이메일·분기·재진입을 사용자와 하나씩 합의 → 정의서 생성 → 저니 생성 전 승인 |
| **자동(Auto)** | 대화 없이 기본값으로 Plan→정의서→저니까지 일괄 진행 |

## 2-3. 저니(Journey) 생성 — SFMC (STEP 3)

정의서를 읽어 SFMC Journey Builder에 저니를 생성합니다.

- **복잡도별 저니 구조**:
  - `단순` — Email → Wait & Exit (분기 없음)
  - `중간` — 분기 1회 (Decision Split 또는 Engagement Split)
  - `복합` — 다단계·중첩 분기 (Decision Split → Email → Wait → Engagement Split)
- **분기 컴포넌트** — Decision Split(속성 기준) · Engagement Split(열람/클릭 반응) · Wait(대기) · Wait & Exit
- **진입 소스 자동화** — 세그먼트+동의 필터로 진입 DE를 Automation SQL Query로 생성·적재
- **멀티 채널** — 이메일(EMAILV2 액티비티) + **알림톡/문자/카카오/SMS**(micrm REST 커스텀 액티비티, 모바일 컨텐츠 seq 참조)
- **스케줄** — `Recurring`(반복 발송) / `On Activation`(발행 시 1회)
- **재진입** — No re-entry / Re-entry anytime / Re-entry only after exiting
- **생성 상태** — 기본 **Draft**(미발행). `발행해줘` 요청 또는 정의서 `auto_publish=TRUE`일 때만 발행
- **이름 중복 처리** — 동일 시나리오명 존재 시 `_v1`, `_v2`… 자동 suffix 부여

## 2-4. 조회 (읽기 전용)

- 저니 목록 · 최근 저니(수정일 최신순) · 상태 · 링크 실시간 조회
- Data Extension · 이메일 에셋 · Automation · Sender Profile 등 SFMC 객체 조회
- 항상 SFMC를 **실시간 조회**(로컬 이력 파일이 아닌)

## 2-5. 온보딩 · 세팅 점검

발송 인프라를 read-only로 진단합니다(설정 변경 없음).

- **점검 카테고리** — A(접속/연동 기반) · C(발송 인증/평판) · D(발송 구성)
- **상태 분류** — `✅ 구성됨` / `⚠️ 점검필요`(행 0개·일시정지·한쪽만 존재 등) / `❌ 수동확인`(콘솔 직접 확인)
- **산출물** — 점검 표 + 잔여 태스크 목록 + (전용 IP 시) IP 워밍 램프 일정 플랜

## 2-6. 인터페이스

- **Claude Code(CLI)** 대화형 조종 (기본)
- **Slack 봇** 조종 (Socket Mode — 이 PC가 켜져 있으면 동작, 공개 IP 불필요)
- **정의서 직접 첨부**(xlsx / CSV / Google Sheets) → STEP 1·2 건너뛰고 바로 저니 생성

# 3. 캠페인 생성 흐름

사용자는 **한 문장만 입력**하고, 이후 STEP 1~4는 오케스트레이터가 담당 워커에 위임해 진행합니다.

```
사용자 한 문장  (예: "신규 회원 캠페인 만들어줘")
   │
   ▼
[STEP 1] 주제 선정      데이터 진단 → 캠페인 추천 (+ 분석 리포트 자동 생성)   → mce-topic-agent
   │                    └ (수동) 후보 표에서 캠페인 선택 / 실행 모드 선택
   ▼
[STEP 2] 기획 / 정의서   Journey Plan 설계 + xlsx 정의서 생성 (수동/자동)      → mce-planning-agent
   │                    └ (수동) Plan 승인
   ▼
[STEP 3] 저니 생성       SFMC Journey Builder에 생성 (기본 Draft)             → mce-journey-agent
   │
   ▼
[STEP 4] 결과 보고       저니 이름·ID·상태·링크 + 흐름도 + 생성 이력 기록       → 오케스트레이터
```

> 자동 모드는 STEP 1~4를 질문 없이 일괄 실행하고 맨 마지막 결과만 1회 보고합니다.
> 정의서를 직접 첨부한 경우 STEP 1·2를 건너뛰고 STEP 3부터 진행합니다.

# 4. 도입 최소 조건 요약

발송까지 실제로 운영하려면 아래 세 축이 완비돼야 합니다.

| # | 축 | 핵심 준비물 |
|---|---|---|
| ① | **SFMC 계정 + API 연동** | 라이선스 · 대상 BU · Installed Package(Scope) · MCP 서버 연결 |
| ② | **적재된 고객 데이터** | 마스터 데이터(원천 테이블) + 분석 핵심 컬럼 + **채널 동의값** |
| ③ | **발송 인증** | 도메인 인증(SAP) · CAN-SPAM 물리 주소 · 구독센터/수신거부 · Sender Profile |

- **①②** 만 있으면 진단·기획·저니 생성(Draft)까지 가능
- **③** 까지 완비되면 실제 발송 가능
- **조건부(E)·선택(F)** 는 알림톡/대량발송/Slack/구글시트를 실제로 쓸 때만 준비

> 발송 준비가 끝나면, **한 문장 입력만으로 진단부터 저니 생성까지** 완성됩니다.
