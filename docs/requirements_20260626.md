# 부록: A·B 완성 변경안 (2026-07-01 확정 대기)

> C는 구현거리가 아니라 주의사항/참고(C2 집계 활용은 A·B에 흡수). **A·B만 완전하게 다듬는다.**

## 기술 제약 (설계 전제)
- **sf-mce는 DE 셀 값을 못 읽고 `rowCount`만 읽는다.** → "몇 명"을 알려면 각 지표를 **개별 count DE의 rowCount**로 떨궈야 함(SEG_ 방식 불가피).
- 따라서 A의 핵심은 "SEG_ 제거"가 아니라 **측정할 세그먼트 목록을 MD에 고정하지 말고, AI가 스키마+의미규칙으로 직접 정하게 하는 것**.

## A 변경안 — 데이터 기반 자율 추천
1. `analysis-guide/ecommerce-default.md`: **§1 스키마 + §2 의미규칙(세금·포인트·동의)만** 실질 내용으로 유지. **§3 기준선·§4 고정 SEG_ 7세트는 "예시/참고"로 강등** (AI가 분포 보고 결정, 기준선은 데이터 기반 또는 "가정 명시").
2. `analysis-guide/_common.md`: **"컬럼 프로파일링 → 캠페인 도출" 절 신설** — 컬럼 타입별 분포 집계(날짜=최근성 / 수치=분포 / Boolean=비율 / 범주=값분포) → 두드러진 지점에서 AI가 캠페인 직접 도출. 측정 세그먼트도 AI가 정해 §6으로 생성.
3. `mce-topic-agent`: "고정 목록 읽기" → "프로파일링 후 도출"로 워크플로우 교체.

## B4 변경안 — 에이전트 3개별 가이드 + 공통/고객사 분리
```
공통(에이전트별)                      고객사(1파일, 섹션 분리)
├ 분석  → _common.md                  analysis-guide/<고객>.md
├ 기획  → journey-build.md (패턴)      ├ §A 분석: 스키마·의미규칙 (완료)
└ 전이  → journey-build + fixed-values ├ §B 기획: 채널·재진입 기본·스케줄 관례
                                       └ §C 전이: BU 고정값(Send Classification·
                                          Publication List·알림톡 applicationExtensionKey·seq)
```
- **전이 에이전트에 하드코딩된 BU 값**(`Cafe24 Online Store 3657`, Send/Sender/Delivery GUID 등)을 **고객사 분석 가이드 §C로 이전** → "고객사 = 파일 1개만 수정" 성립.
- 각 에이전트가 "자기 공통 MD + 활성 고객사 해당 섹션"을 읽도록 일관 배선.
