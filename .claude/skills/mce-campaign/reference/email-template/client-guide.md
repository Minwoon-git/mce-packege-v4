# 이메일 콘텐츠 — 고객사 도입·운영 가이드

고객사가 이 이메일 콘텐츠 생성을 **실제 운영에 어떻게 쓰는지**의 흐름. (예시: 후지필름몰)

> 이 문서는 *운영 흐름*이다. *생성 기술 규칙*(토큰·born-compliant·이미지 업로드)은 [`_guide.md`](_guide.md)가 SSOT.
> *캠페인 전체 절차(STEP1→2→3)* 는 [`SKILL.md`](../../SKILL.md)가 SSOT — 여기서 반복 설명하지 않는다.

---

## ① 한 번만 세팅 (고객사 온보딩)

고객사 BU에 최초 1회. 이후 캠페인마다 다시 안 한다.

| 항목 | 내용 | 산출물 |
|---|---|---|
| **브랜드 킷** | 로고·색·폰트·버튼모양 정의 (홈페이지 추출 or 고객사 제공) | `<고객사>.json` |
| **계정 정보** | Account Information에 **물리주소** 입력 → `%%Member_Addr%%` 등이 실제 값으로 채워짐 | 계정 설정 |
| **발송 인프라** | Sender Profile·Send Classification·수신거부/프로필센터·도메인 인증·전용 IP 워밍 | [`mce-onboarding`](../../../mce-onboarding/SKILL.md) 스킬로 점검 |
| **브랜드 이미지** | 로고·상시 배너를 콘텐츠 빌더에 1회 업로드 → `publishedURL`을 브랜드 킷에 저장 | 이미지 asset + URL (C 경로) |

## ② 캠페인마다 반복

고객사 담당자가 **한 문장**으로 요청 → 오케스트레이터가 STEP1→2→3 수행 (절차는 SKILL.md).
콘텐츠 생성 단계에서 **고정 템플릿 + `<고객사>.json` + 이번 캠페인 카피/이미지**로 born-compliant HTML을 콘텐츠 빌더에 Draft 생성하고, 그 `emailId`를 저니 이메일 액티비티에 연결한다.

> **매 캠페인 바뀌는 것 = 카피·상품 이미지뿐.** 브랜드 룩·필수 코드는 고정 템플릿+킷이 자동 보장.

## ③ 역할 분담 (중요)

| 주체 | 담당 |
|---|---|
| **이 도구 (자동)** | 브랜드 반영 + 규정 통과 초안을 콘텐츠 빌더에 자동 생성 |
| **고객사 마케터** | 카피·오퍼·상품 **확정**, 초안 검토, 신상품 이미지 제공 |
| **고객사 (최종)** | 검토·승인 후 **발송 결정** |

> ⚠️ 도구는 임의 발송하지 않는다 — 기본 **Draft**. 발송은 명시적 지시가 있을 때만. (SKILL.md STEP3 ③ 발행 규칙)
> ⚠️ 카피·오퍼·이미지는 **고객사가 확정**한다. AI가 지어낸 값은 *시안*이지 실발송본이 아니다.

## ④ 실제 발송 전 필수 조건 (Go-live 체크리스트)

- [ ] 고객사 **실 BU** + 발신 인프라 (테스트 BU 아님)
- [ ] 브랜드 이미지가 **콘텐츠 빌더에 업로드**됨 (고객사 CDN 직링크 X — 발송 후 깨짐 방지)
- [ ] **구독자 DE** 존재 (개인화 필드 `FirstName` 등 포함)
- [ ] 카피·오퍼 확정 + **사람 검수** (브랜드·법무)
- [ ] Account Information 물리주소 입력됨 (CAN-SPAM)

## 부록 — 생성 모드 (시안 vs 실발송)

| 모드 | 크리에이티브 출처 | 용도 |
|---|---|---|
| **C. 스크래치** | AI가 카피·디자인 창작 | **시안·PoC** (예: 오늘 후지필름 미리보기) |
| **B. 템플릿 채우기** | 고객사 브랜드값 + 확정 카피/이미지 | 반복 캠페인 (권장 실발송) |
| **A. HTML 랩핑** | 디자이너가 만든 완성 HTML | 최고 완성도 필요 시 |

실발송은 **A/B**, 시안은 **C**. C 결과물엔 항상 "시안 — 검수 전" 표시.
