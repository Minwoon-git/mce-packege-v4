# 분석 리포트 생성 가이드 (D1) — 품질 기준 SSOT

> 고객 전달용 **데이터 분석 & 캠페인 추천 리포트**의 **구조·내용·디자인**을 고정하는 문서.
> 리포트를 만들 땐 **반드시 이 가이드를 따른다.** 데이터만 바뀌어도 항상 같은 고품질로 나오게 하는 게 목적이다.
>
> ## ⏱️ 언제 생성하나 (트리거) — STEP 1 진단 직후
> **갈래 A(생성 가능한 캠페인 리스트업/진단) 완료 시, 진단 결과로 이 리포트를 자동 생성**한다. 위치: STEP 1 끝 ~ 캠페인 선택 전. 결과 보고 시 리포트 파일 경로를 함께 제시한다.
> (갈래 B처럼 특정 캠페인 의도가 명확하면 리포트는 생략 가능 — 리스트업/진단 요청일 때 생성.)
>
> ## 형식 — PPT 리포트 (기본·유일)
> ⭐ **리포트는 PPTX만 생성한다. HTML/Artifact 리포트는 만들지 않는다.** (2026-07 결정)
> ⭐⭐ **2026-07-29부터 리포트는 "빌더 + 데이터 JSON" 방식으로만 만든다** — 디자인·레이아웃은 [`report-builder/gen_report.js`](report-builder/gen_report.js)에 고정돼 있고, **AI는 진단 결과로 데이터 JSON(§6 계약)만 작성해 빌더를 실행**한다. 슬라이드 코드를 매번 새로 작성하지 않는다(품질 편차의 원인). 절차는 §7.
> - **디자인 SSOT = `gen_report.js`** (토큰·레이아웃·모티프가 코드로 고정). `report-template.html`은 레거시 참고용으로만 남긴다.
> - 데이터 계약 예시 = [`report-builder/sample-data.json`](report-builder/sample-data.json) · 검증 샘플 = `reports\고객데이터_분석리포트_샘플_20260729.pptx`

## 0. 원칙 (모든 슬라이드에 적용)

1. **제목 = 주제형, 부제 = 결론.** 본문 슬라이드(2~6)의 제목 블록은 2단이다 — **큰 제목은 주제형 명사구**("세그먼트 진단", "기회 우선순위" — 전통 보고서 형태), **바로 아래 부제 한 줄이 그 슬라이드의 결론**을 말한다(예: "규모 상위 세 축은 1회성 구매자·휴면·이탈위험"). 부제 없는 본문 슬라이드는 금지 — 결론 없는 주제 나열이 된다. **제목·부제 모두 "~합니다/~입니다" 서술형 어미 금지, 명사(구) 종결.** 본문·해석·각주 문장은 서술형(~니다)을 유지한다. 표지 부제·마무리 헤드라인도 명사형 종결.
2. **숫자 → 해석 → 액션** 순서. 수치를 나열하지 말고, 그 수치가 **왜 중요한지 + 무엇을 하자**로 연결한다.
3. **모든 수치는 진단 실측값 또는 실측값의 산술 유도값.** 지어내지 않는다. 기준선을 가정했으면 각주로 밝힌다.
4. **수치 표기는 전 슬라이드 소수 1자리로 통일.** 한 덱에서 64.7%와 65%를 섞지 않는다.
5. **분모를 항상 밝힌다.** 구매자 대비/전체 대비가 섞이면 행 단위 칩·라벨로 분리 표기하고 각주로 분모 수를 명시한다. 세그먼트가 상호 중복이면 "중복 포함(합계≠모수)"을 각주에 넣는다.
6. **동의 필터 전/후를 구분해 말한다.** 세그먼트 규모는 "동의 필터 적용 전"임을 명시하고, 세그먼트별 도달 가능 인원을 집계했으면 함께 표기한다(§6 확장 집계). 집계 전이면 "발송 대상은 캠페인 확정 시 동의 필터 반영"으로 정직하게 쓴다.
7. **담백한 비즈니스 톤.** 과장·이모지·AI 말투 금지. 고객 임원이 읽는다는 전제.
8. **한 슬라이드 = 한 메시지.** 정보 과밀 금지. 단, 하단을 방치하지 않는다 — 모든 본문 슬라이드는 러닝 푸터(§2)로 마감한다.

## 1. 구조 (7슬라이드 — 빌더 고정)

| # | 슬라이드 | 배경 | 목적 | 핵심 내용 |
|---|---|---|---|---|
| 1 | **표지** | 다크 | 톤 세팅 | 리포트명 · 부제(결론 티저) · 모수/기준일/업종/분석 소스 · 로고 자리 · SAMPLE 칩(샘플일 때) |
| 2 | **핵심 요약** | 라이트 | 30초 안에 결론 | 결론형 헤드라인 + 서술 + 스탯 카드 3개(수치/라벨/해석 3단) + 권장 우선순위 밴드(①→②→③) |
| 3 | **고객 기반 구조** | 라이트 | 핵심 주장 증명 | 재구매 퍼널(전체→구매자→재구매자, 전환율 표기) + 도달 가능성 패널(도달/미동의 스택바) + 해석 박스 |
| 4 | **세그먼트 진단** | 라이트 | 현황을 데이터로 | 바-테이블(내림차순, 상위 3 강조, 제약 세그먼트 점선, 분모 칩) + 해석 박스 + 분모·중복 각주 |
| 5 | **기회 우선순위** | 라이트 | 무엇을 먼저 | 순위 밴드 5행(순위·캠페인·근거 칩·대상·기대 임팩트, 상위 3 틴트) + 서술 + 미니 스탯 |
| 6 | **핵심 캠페인 상세** | 라이트 | 상위 3개 실행안 | 카드 3개(대상 인원 앵커 · 채널 칩 · 메시지 방향 · **측정 지표(베이스라인)** · 기대효과 밴드) |
| 7 | **마무리** | 다크 | 결론 + 신뢰성 | 종합 결론 + 핵심 수치 3개 재소환(저대비) + 방법론·한계 각주 |

> 데이터가 빈약하면 3번(퍼널/도달)을 줄이고, 풍부하면(§6 확장 집계 확보 시) 채널 4분면·금액 환산을 3·5번에 반영한다.
> ⚠️ "다음 단계(선택→DE생성→저니)" 프로세스 섹션은 **넣지 않는다** (리포트는 분석·추천까지. 실행 흐름은 시스템이 처리).

## 2. 디자인 시스템 — 고급 중립 (브랜드 미정)

> 토큰·레이아웃은 **`gen_report.js` 상단 토큰 블록에 코드로 고정**돼 있다. 아래는 그 요약이며, 바꿀 땐 빌더를 수정한다(§5).

### 컬러 토큰
| 역할 | HEX | 용도 |
|---|---|---|
| `INK` (주색) | `1A2238` | 다크 배경, 제목, 강조, 주 막대 |
| `INK_BG` | `141B2E` | 표지·마무리 배경 |
| `TEXT` / `MUTE` | `2B3245` / `6B7280` | 본문 / 캡션·보조 |
| `LINE` / `CARD` | `E5E8EE` / `F7F8FB` | 구분선 / 카드 틴트 |
| `ACCENT` | `0E9F8E` (절제된 틸) | 포인트만: 키커 도트·우선순위 번호 칩·퍼널 마지막 단·% 단위. 남발 금지(10% 이하) |
| `ACCENT_SOFT` / `ACCENT_DARK` | `E7F4F1` / `0B3F39` | 해석 박스·기대효과 밴드 / 그 위 텍스트 |
| `BAR_REST` | `B7BFD0` | 강조 외 막대(상위 축과 위계 분리) |
| `TOP_TINT`/`TOP_LINE` | `F1F8F6`/`CBE4DE` | 우선순위 상위 3행 배경/테두리 |

### 타이포그래피 (한국어)
- 폰트: **맑은 고딕** 단일. 크기·굵기로만 위계.
- 슬라이드 제목 27pt bold / 표지 타이틀 40pt / 스탯 숫자 52pt bold(+단위 22pt ACCENT) / 본문 11~14.5pt / 캡션·각주 8.5~10.5pt MUTE.

### 레이아웃·모티프 규칙 (AI 티 방지 핵심)
- 마진 0.7", 블록 간격 0.3~0.4" 일관. **하단은 러닝 푸터로 마감** — 본문 슬라이드(2~6) 좌측 y=7.06"에 각주(없으면 리포트명·기준일), 우측에 페이지 번호(9pt MUTE). 하단 1인치 이상을 빈 띠로 남기지 않는다.
- **도트 모티프 배치 규칙은 하나**: ACCENT 원형 도트(0.12")는 항상 **키커(섹션 라벨) 좌측**에만. 카드 코너 등 다른 위치에 흩뿌리지 않는다.
- 다크 슬라이드(1·7) 시각 앵커: 우측에 **동심원 링 모티프**(`DK_RING 222C47` 얇은 원 2~3개 + ACCENT 도트 1개). 텍스트만 있는 빈 다크 화면을 만들지 않는다.
- 카드: `ROUNDED_RECTANGLE` + CARD 틴트 + 부드러운 그림자(blur 8, offset 3, opacity 0.10). 스탯 카드는 **수치 / 라벨(볼드) / 구분선 / 해석 1줄** 3단 구성.
- **차트는 도형 기반 바**(pptxgenjs 도형 = 벡터·편집 가능, 이미지 금지): 내림차순 정렬(최대가 맨 위), 상위 축 INK·나머지 BAR_REST, **제약 세그먼트(미동의 등)는 점선 아웃라인**으로 성격 분리, 값 라벨은 바 우측, 비율은 우측 열에 이중 인코딩, 분모는 행별 칩. (네이티브 `addChart`도 허용되나 정렬·부분 강조가 어려워 바-테이블을 기본으로 한다.)

### 🚫 금지 (AI 티/조잡함)
- 제목 밑줄, 슬라이드 폭 색 바, 카드 엣지 스트라이프, 사이드바 띠 — **전부 금지**.
- 본문 중앙정렬(제목·칩 라벨만 예외), 크림/베이지 배경, 텍스트 박스 넘침, 저대비 텍스트, 근거 없는 수치, 과장 문구, 이모지.
- **고아 줄바꿈**: 마침표·한 글자가 다음 줄에 홀로 남는 문장, "2차"처럼 단위가 쪼개지는 라벨 — 텍스트를 다듬거나 박스 폭을 조정해 없앤다(QA 확인 항목).

## 3. 내용 작성 규칙 (슬라이드별)

- **표지**: 리포트명 + **부제 1줄 = 결론 티저, 명사형**(예: "성장 레버는 확보 고객의 두 번째 구매"). 메타 4종(모수·기준일·업종·분석 소스). 샘플이면 SAMPLE 칩. 로고는 `meta.logo`로 주입(없으면 비움).
- **핵심 요약**: 스탯 카드 3개 — 각 카드 = 큰 수치 + 라벨(세그먼트·인원) + **해석 1줄(왜 기회인가, 정의 반복 금지)**. 카드 구성 권장: 최대 기회(1회성) · 시급성(이탈위험) · **도달 가능 모수(임원의 "몇 명한테 보낼 수 있나" 답)**. 하단 = 권장 우선순위 밴드(번호 칩 ①②③ + 캠페인명 + 근거 1구). 분모 각주 필수.
- **고객 기반 구조**: 퍼널 3단(전체→구매자→재구매자)에 단계별 전환율 표기 — 리포트 전체 주장("두 번째 구매가 레버")을 그림 하나로 증명하는 슬라이드. 우측 도달 가능성 패널(도달 vs 미동의 + 재수집 필요 노트). 유도값 산식은 각주에(재구매자=구매자−1회성 등).
- **세그먼트 진단**: 바-테이블 내림차순. 해석 박스 필수(표·차트만 두지 않는다). 해석은 핵심 요약 문장의 반복이 아니라 **이 슬라이드 고유 정보**(제약 세그먼트 처리, 다음 장 연결)로.
- **기회 우선순위**: 비율·임팩트 기준 순위. 각 행에 근거(세그먼트 %) 칩·대상 규모·기대 임팩트(정성이라도 "왜 지금"을 붙임). 서술에 **중복 포함 여부와 동의 필터 전/후**를 명시. 미니 스탯(상위 3 접점 합)으로 규모감 제시.
- **핵심 캠페인 상세**: 카드마다 **대상 인원을 시각 앵커(23pt)로**, 채널 칩 + "동의 필터 적용" 통일 표기, 메시지 방향(가능하면 보유 쿠폰·포인트 등 **추가 비용 없는 레버** 언급), **측정 지표 = 현재 베이스라인이 있는 재집계 가능 지표**(예: 재구매 전환율 35.3% 대비 추적). 오픈/클릭 등 반응 지표는 "발송 이력 축적 후"로 구분.
- **마무리**: 결론 헤드라인 + 우선순위 재확인 + 핵심 수치 3개 저대비 재소환. **방법론 + 한계**(이 버전이 다루지 않는 것 — 금액 환산·교차·채널 분해 등 미산출 항목)를 정직하게 명시.

## 4. 품질 체크리스트 (생성 후 반드시 확인)

- [ ] 본문 슬라이드마다 **주제형 제목 + 결론 부제** 2단 구조인가 / 제목·부제가 **명사형 종결**인가 ("~니다" 금지, 본문은 서술형 유지) / 연속 부제에 같은 구문 반복 없나
- [ ] 모든 수치가 **실측·유도값**인가 / 표기가 전 슬라이드 **소수 1자리로 통일**됐나 / 가정·산식은 각주에 있나
- [ ] **분모**가 행/카드 단위로 표기됐나 / 세그먼트 **중복 포함** 각주 있나 / **동의 필터 전/후** 구분했나
- [ ] 진단·기반 슬라이드에 **해석 문장**이 있나 (표·차트만 덩그러니 금지) / 추천마다 **기대 임팩트** 있나 / 캠페인 카드에 **측정 지표(베이스라인)** 있나
- [ ] 바 정렬이 **내림차순**이고 상위 축 강조·제약 세그먼트 점선이 적용됐나
- [ ] 금지 요소(액센트 바·밑줄·중앙정렬 본문·크림 배경) 없나 / ACCENT 남용 없나 / 도트 모티프가 키커 좌측 규칙을 지켰나
- [ ] **텍스트 넘침·겹침·고아 줄바꿈** 없나 (한글 카드 본문·마무리 서술 특히) — PNG 렌더로 실제 확인
- [ ] 본문 슬라이드에 **러닝 푸터+페이지 번호** 있나 / 표지에 로고 자리·부제 있나

## 6. 데이터 계약 (진단 결과 → JSON — 빌더 입력)

> AI가 작성하는 것은 **이 JSON 하나**다. 전체 예시 = [`report-builder/sample-data.json`](report-builder/sample-data.json). 서술 필드는 `[{t,b,accent}]` 런 배열(볼드/액센트 강조).

| 키 | 채울 값 |
|---|---|
| `meta` | kicker·title·**subtitle(결론 티저)**·population·baseDate·industry·source·**sample(불리언→SAMPLE 칩)**·logo |
| `summary` | **title(주제형)·subtitle(결론 부제)**·narrative(런)·stats 3개(value/unit/label/**sub=해석 1줄**)·priority 3개(name/why)·footnote(분모 각주) |
| `base` | title·subtitle·퍼널 funnel[]({label,value,display,conv})·reach(도달/미동의)·insight·footnote(유도 산식) |
| `segments` | title·subtitle·rows[]({label,count,display,ratio,denom,top,**constraint(점선)**})·insight·footnote |
| `opportunities` | title·subtitle·rows[]({rank,name,basis,target,impact,top,**reachable?**})·narrative(중복·필터 명시)·stat(미니 스탯)·footnote |
| `campaigns` | title·subtitle·cards[]({name,target,targetSub,channels[],channelNote,message,**kpi(베이스라인 포함)**,impact,**reachable?**})·footnote |
| `closing` | headline·narrative(런)·stats 3개(재소환)·methodology(**방법론+한계**) |

### 기본 집계 (STEP 1 진단 필수 — 항상 채움)
전체 모수 · 구매자 · 1회성 · 이탈위험 · 휴면 · 미동의 · 장바구니 · 첫구매 미전환 + **유도값**: 재구매자(구매자−1회성) · 도달 가능(전체−완전 미동의) · 전환율(구매/재구매).

### 확장 집계 (가능하면 산출해 주입 — 리포트 디테일이 한 단계 올라감)
RECON_Profile에서 전부 집계 가능. 산출했으면 해당 필드/서술에 반영하고, 못 했으면 `closing.methodology`의 "한계"에 미산출 항목으로 명시한다(지어내지 않는다):
1. **세그먼트별 도달 가능 인원** — 세그먼트 조건 AND (email_consent OR sms_consent) → `rows[].reachable`·`cards[].reachable`
2. **채널 4분면** — email×sms 동의 TT/TF/FT/FF 카운트 → base.reach 서술 보강
3. **금액 환산** — SUM(cart_total_amount)(장바구니 회수 대상 금액), SUM/AVG(total_spent)(이탈위험 노출 고객 자산) → 임팩트·서술에 ₩로
4. **세그먼트 교차** — 1회성∩이탈위험, 이탈∩휴면 → 중복 구조·순유효 대상 서술
5. **개인화 근거** — preferred_category 상위, unused_coupon_count>0 보유자 → 캠페인 카드 메시지 방향
6. **최근성 분포** — last_order_date 경과일 버킷 → 90일 기준선 타당성

## 7. PPT 산출 절차 (SSOT)

1. **데이터 JSON 작성**: STEP 1 진단 결과로 §6 계약에 맞춰 `reports\report-data_YYYYMMDD.json` 작성. (`sample-data.json`을 복사해 값·문장을 교체하는 방식 권장 — 문장도 데이터에 맞게 다시 쓴다, 샘플 문장 복붙 금지)
2. **빌드**: 프로젝트 루트에서
   `node .claude\skills\mce-campaign\reference\report-builder\gen_report.js reports\report-data_YYYYMMDD.json reports\고객데이터_분석리포트_YYYYMMDD.pptx`
3. **QA (렌더링)**: PowerPoint COM으로 PNG 내보내 §4 체크리스트 확인 —
   `PowerPoint.Application` → `Presentations.Open(path,-1,0,0)` → `Slides.Item(n).Export(png,"PNG",1600,900)`
   (LibreOffice가 있으면 soffice 변환도 가능. 텍스트 넘침·고아 줄바꿈 발견 시 **JSON 문장을 다듬어** 재빌드 — 빌더 코드는 건드리지 않는다.)
4. **출력 경로**: `<프로젝트 루트>\reports\` · 파일명 `고객데이터_분석리포트_YYYYMMDD.pptx`
