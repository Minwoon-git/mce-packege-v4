# 분석 리포트 생성 가이드 (D1) — 품질 기준 SSOT

> 고객 전달용 **데이터 분석 & 캠페인 추천 리포트**의 **구조·내용·디자인**을 고정하는 문서.
> 리포트를 만들 땐 **반드시 이 가이드를 따른다.** 데이터만 바뀌어도 항상 같은 고품질로 나오게 하는 게 목적이다(참석자 2 "MD만 잘 쓰면 깔끔하게").
>
> ## ⏱️ 언제 생성하나 (트리거) — STEP 1 진단 직후
> **갈래 A(생성 가능한 캠페인 리스트업/진단) 완료 시, 진단 결과로 이 리포트를 자동 생성**한다. 위치: STEP 1 끝 ~ 캠페인 선택 전(참석자 2의 "분석 → 리포트 → 시나리오 추천" 흐름의 리포트 자리). 결과 보고 시 리포트 링크를 함께 제시한다.
> (갈래 B처럼 특정 캠페인 의도가 명확하면 리포트는 생략 가능 — 리스트업/진단 요청일 때 생성.)
>
> ## 형식 — 자체완결 HTML 웹 리포트 (기본)
> **읽는 문서형 HTML**(발표 덱 아님). 단일 파일, 외부 의존 없음. 브라우저에서 열고 인쇄하면 PDF로도 뽑힘. 아티팩트로 게시해 바로 열람 가능.
> - **재사용 템플릿(디자인·구조 SSOT)**: [`report-template.html`](report-template.html) — 이 파일의 **CSS·레이아웃을 그대로 쓰고, 데이터 부분만 교체**한다. 손으로 CSS를 새로 짜지 않는다.
> - (선택) PPT가 필요하면 `pptxgenjs`로 같은 구조를 만들 수 있으나 기본은 HTML.
> - 참조 데이터: STEP 1 진단 결과(모수·세그먼트·비율·추천) + 활성 고객사 분석 가이드(지표 정의·기준선·채널).

---

## 0. 원칙 (모든 슬라이드에 적용)

1. **헤드라인 = 결론.** 슬라이드 제목이 "무엇을 봤나"가 아니라 "그래서 무엇인가"여야 한다. (예: "진단 결과" ❌ → "구매자의 65%가 재구매 없이 이탈 직전" ✅)
2. **숫자 → 해석 → 액션** 순서. 수치를 나열하지 말고, 그 수치가 **왜 중요한지 + 무엇을 하자**로 연결한다.
3. **모든 수치는 진단 실측값.** 지어내지 않는다. 기준선을 가정했으면 각주로 밝힌다.
4. **담백한 비즈니스 톤.** 과장·이모지·AI 말투 금지. 고객 임원이 읽는다는 전제.
5. **한 슬라이드 = 한 메시지.** 정보 과밀 금지. 여백을 남긴다.

## 1. 구조 (문서 섹션)

| 순서 | 섹션 | 목적 | 핵심 내용 |
|---|---|---|---|
| — | **마스트헤드** (다크 밴드) | 톤 세팅 | 리포트명 · 모수 · 기준일 · 업종 (로고 자리) |
| 01 | **핵심 요약** | 30초 안에 결론 | 분석 서술 + 핵심 수치 3개(스탯 + 해석) + 우선순위 한 줄 |
| 02 | **진단** | 현황을 데이터로 | 세그먼트 막대차트 + 표(지표·인원·비율·정의) + **해석 박스**(단순 표 금지) |
| 03 | **기회 우선순위** | 무엇을 먼저 | 추천 캠페인 순위 + 근거(비율) + 대상 규모 + **기대 임팩트** + 서술 |
| 04 | **핵심 캠페인 상세** | 상위 2~3개 실행안 | 캠페인별 대상·채널·메시지 방향·기대효과 |
| — | **방법론 각주** (footer) | 신뢰성 | 분모 기준·데이터 기준일·기준일수 |

> 마스트헤드는 **다크**, 본문은 **라이트**. 데이터가 빈약하면 04를 2개로 줄이고, 풍부하면 02·03을 쪼갠다.
> ⚠️ "다음 단계(선택→DE생성→저니)" 프로세스 섹션은 **넣지 않는다** (리포트는 분석·추천까지. 실행 흐름은 시스템이 처리).

## 2. 디자인 시스템 — 고급 중립 (브랜드 미정)

> 브랜드 자산이 없을 때의 기본. **로고·컬러·폰트는 아래 토큰 한 곳만 바꾸면 브랜드 적용**되도록 파라미터화한다(§5).

### 컬러 토큰
| 역할 | HEX | 용도 |
|---|---|---|
| `INK` (주색) | `1A2238` | 다크 배경, 제목, 강조 |
| `INK_BG` | `141B2E` | 표지·마무리 배경 |
| `TEXT` | `2B3245` | 본문 |
| `MUTE` | `6B7280` | 캡션·보조 |
| `LINE` | `E5E8EE` | 표·구분선 |
| `CARD` | `F7F8FB` | 카드 배경 틴트 |
| `ACCENT` | `0E9F8E` (절제된 틸) | 포인트 1곳(숫자·모티프)만. 남발 금지 |
| `WHITE` | `FFFFFF` | 라이트 배경·다크 위 텍스트 |

> **60-30-10**: INK/뉴트럴이 화면의 60-70%, 서브 뉴트럴 30%, ACCENT는 10% 이하. ACCENT를 여러 곳에 쓰지 않는다.

### 타이포그래피 (한국어)
- 폰트: **맑은 고딕**(Windows PowerPoint 기본 한글). 제목 볼드, 본문 레귤러로 위계.
- 크기: 슬라이드 제목 30~36pt bold / 섹션 헤더 18~20pt bold / 본문 13~15pt / 캡션 10~11pt MUTE / 스탯 숫자 48~60pt bold.

### 레이아웃 규칙
- 마진 **0.6"** 이상, 블록 간격 0.3~0.4" 일관.
- 카드: `ROUNDED_RECTANGLE` + `CARD` 틴트 + 부드러운 그림자(`blur 8, offset 3, opacity 0.10`). **엣지 액센트 바 금지.**
- 모티프: **작은 ACCENT 원형 도트**(0.2")를 카드/섹션에 반복. 이 하나로 통일.
- 차트: **네이티브**(이미지 금지), `chartColors`=INK 계열, 데이터라벨 표시, 축·그리드 최소화, 범례는 단일 시리즈면 숨김.

### 🚫 금지 (AI 티/조잡함)
- 제목 밑줄, 슬라이드 폭 색 바, 카드 엣지 스트라이프, 사이드바 띠 — **전부 금지**.
- 본문 중앙정렬(제목만 중앙 가능), 크림/베이지 기본 배경, 텍스트 박스 넘침, 저대비 텍스트.
- 근거 없는 수치, 과장 문구, 이모지.

## 3. 내용 작성 규칙 (슬라이드별)

- **표지**: 리포트명 "고객 데이터 분석 & 캠페인 추천". 부제에 모수·날짜·업종. 우상단 **로고 자리**(브랜드 없으면 비움).
- **핵심 요약**: 진단에서 **비중·임팩트 상위 3개**를 스탯 카드로. 각 카드 = 큰 수치 + 라벨(인원) + **해석 1줄**(왜 기회인가). 하단에 종합 메시지 1줄("가장 큰 기회는 ~").
- **진단**: 세그먼트 분포를 **막대 차트**로, 옆에 표(지표·인원·비율). **차트 아래/옆에 해석 문장**을 반드시 넣는다(표만 두지 않는다). 분모(구매자 vs 전체)를 각주로.
- **기회 우선순위**: 비율 높은 순 추천. 각 항목에 **근거(세그먼트 %)·대상 규모·기대 임팩트**. 임팩트는 정성("재구매율↑·LTV↑")이라도 반드시. 상위 3개 시각 강조.
- **핵심 캠페인 상세**: 상위 2~3개. 카드마다 **대상 인원·채널·메시지 방향·기대효과**. 채널은 분석 가이드 동의 규칙 반영(이메일=email_consent 등).
- **다음 단계**: ①캠페인 선택 ②발송 대상 DE 자동 생성(조건+동의 필터) ③Journey 생성. 번호 프로세스로.

## 4. 품질 체크리스트 (생성 후 반드시 확인)

- [ ] 모든 슬라이드 **제목이 결론형**인가 (현황 나열 제목 금지)
- [ ] 모든 수치가 **진단 실측값**인가 / 가정 기준선은 각주 표기했나
- [ ] 진단 슬라이드에 **해석 문장**이 있나 (표·차트만 덩그러니 금지)
- [ ] 추천마다 **기대 임팩트**가 있나
- [ ] 금지 요소(액센트 바·밑줄·중앙정렬 본문·크림 배경) **없나**
- [ ] **텍스트 넘침·겹침** 없나 (특히 한글 카드 본문) — PowerPoint에서 실제 확인
- [ ] ACCENT 남용 없나(10% 이하), 다크/라이트 샌드위치 유지했나
- [ ] 로고 자리 확보돼 있나(브랜드 적용 대비)

## 5. 브랜드 교체 지점 (나중에 브랜드 나오면 여기만)

`report-template.html` 상단 **`:root` CSS 토큰 한 곳**만 바꾸면 전체 리브랜딩:
- `--ink`/`--accent`/`--dark` 등 컬러 토큰 → 브랜드 컬러
- `--sans` 폰트 스택 → 브랜드 폰트
- 마스트헤드에 로고(`<img>` data URI) 추가
> 즉 디자인도 **"토큰 = 브랜드"** 로 분리해, 분석 가이드처럼 고객사별로 교체 가능하게 둔다. (색·폰트·로고가 고객사별 값, 구조·규칙이 공통.)

## 6. 생성·QA 절차 (HTML)

1. STEP 1 진단 결과(모수·세그먼트별 인원·비율·추천 캠페인·기준일)를 입력으로 확보.
2. **`report-template.html`을 복제**해 `reports/고객데이터_분석리포트_YYYYMMDD.html`로 저장하고, **데이터 부분만 교체**한다(아래 "데이터 주입 지점"). CSS·구조는 건드리지 않는다.
3. **콘텐츠 QA**: 수치가 진단 실측값과 일치하는지, 막대 폭(값/최댓값 %)·표·합계가 맞는지, 플레이스홀더 잔여 없는지 확인.
4. **게시**: `Artifact` 도구로 게시해 열람 링크 제공. (HTML은 미리보기 패널·브라우저로 바로 렌더되므로 시각 확인 용이.)
5. §4 체크리스트 통과 후 결과 보고에 링크 포함.

### 데이터 주입 지점 (템플릿에서 교체할 값)
- 마스트헤드: 모수·기준일·업종 (+ 로고)
- 핵심 요약: 서술 문장 + 스탯 3개(수치·라벨·해석)
- 진단: 막대차트 6개(라벨·`width:%`=값/최댓값·값) + 표(지표·인원·비율·정의) + 해석 박스
- 기회 우선순위: 표 6행(순위·캠페인·근거·대상·기대 임팩트) + 서술
- 핵심 캠페인 상세: 상위 3개(대상·채널·메시지·기대효과)
- 각주: 분모 기준·기준일수

> 출력 경로: `<프로젝트 루트>\reports\` · 파일명 `고객데이터_분석리포트_YYYYMMDD.html`.
